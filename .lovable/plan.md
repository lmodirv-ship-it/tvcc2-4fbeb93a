# إدارة السيرفرات — أدوات تشغيل وربط ومزامنة لحظية

الهدف: تحويل `/servers` من مراقبة إلى **تحكّم فعلي**: تشغيل مواقع وخدمات، ربطها بقواعد بيانات محلية أو سحابية، تخزين لحظي لكل موقع مُثبتة ملكيته، وربط المنافذ بين المواقع والسيرفرات ليستفيد موقع من خدمة موقع آخر.

## 1. تشغيل المواقع والخدمات (Runtime Control)

- تبويب «التشغيل» داخل تفاصيل السيرفر: لكل موقع مُسجَّل — حالة الخدمة (running/stopped/failed)، الذاكرة، آخر إعادة تشغيل، وأزرار تشغيل / إيقاف / إعادة تشغيل / سجلات مباشرة.
- أوامر وكيل جديدة: `site_start`, `site_stop`, `site_restart`, `site_logs`, `unit_write` (توليد وحدة systemd للموقع من قالب: Node / PHP-FPM / Docker / Static).
- «تشغيل موقع من الصفر»: اختيار السيرفر + النطاق + نوع التشغيل + المنفذ ⇒ إنشاء المجلد، وحدة systemd، بلوك Nginx، شهادة SSL، ثم تسجيله في `site_services`. كل خطوة قابلة لإعادة التشغيل منفردة (نفس نمط `site_provisioning` الحالي).
- كل عملية تدعم Dry Run وتُسجَّل في `operation_log`.

## 2. ربط المواقع بقواعد البيانات (محلية أو سحابية)

- جدول `site_databases`: الموقع ← قاعدة البيانات (من `databases`)، نوع الاتصال (محلي على نفس السيرفر / عبر شبكة داخلية / سحابي)، الدور (primary / replica / readonly).
- زر **Connect** واحد: اللوحة تنشئ قاعدة/مستخدماً على السيرفر عند الحاجة (`db_create`, `db_user_grant`)، تخزّن كلمة المرور مشفّرة في `vault_secrets`، وتحقن `DATABASE_URL` تلقائياً في `website_env_vars` — لا يكتب المستخدم أي مفتاح.
- زر **Test** يفحص الاتصال فعلياً من السيرفر (`db_ping`) ويعرض زمن الاستجابة.
- دعم الربط عبر منفذ مُجسَّر عندما تكون القاعدة على سيرفر آخر (يستخدم جسور `port_links` الحالية بدل فتح المنفذ للإنترنت).

## 3. المزامنة اللحظية والتخزين لكل موقع

- **إثبات الملكية أولاً**: بعد نجاح تحقق TXT (`tvcc-verify=`) الحالي، تُنفَّذ تلقائياً سلسلة: إنشاء `/var/www/<domain>` على السيرفر، إنشاء سجل في `storages`، كتابة ملف هوية `/var/www/<domain>/.tvcc/site.json` (معرّف الموقع، المالك، مفتاح المزامنة، وقت التحقق) — هذا الملف هو مرجع الوكيل لمعرفة ما يخصّ هذه اللوحة.
- **التخزين اللحظي**: الوكيل يراقب مجلد كل موقع مُثبت (inotify) ويرفع التغييرات إلى مساحة الموقع خلال ثوانٍ، مع رفع/تنزيل/حذف من اللوحة في الاتجاه المعاكس. جدول `storage_events` لسجل آخر العمليات وحجم الاستهلاك الفعلي.
- **مزامنة بين السيرفرات**: للمواقع الموجودة في عنقود (`site_clusters`) — مزامنة مستمرة primary ⇐ replicas بفاصل قابل للضبط (5 ثوانٍ … 5 دقائق) أو عند كل تغيير، مع حالة «متزامن / متأخر / فشل» وزر «مزامنة الآن».

## 4. ربط المنافذ والخدمات بين المواقع والسيرفرات

- توسيع `port_links` الحالي بنوع رابط جديد: **service link** — موقع A يستهلك خدمة موقع/سيرفر B.
- زر Connect في صفحة الموقع: اختيار الخدمة من كتالوج الخدمات المكتشفة عبر كل السيرفرات (قواعد بيانات، Redis، n8n، نماذج AI، أي منفذ منشور) ⇒ اللوحة تنشئ الجسر المطلوب على السيرفر المستهلك وتحقن العنوان والمفاتيح في `website_env_vars` مباشرة.
- شرط الوصول: الخدمة تبقى مغلقة على الإنترنت؛ الاتصال يمر عبر جسر داخلي فقط + قاعدة جدار ناري محدودة بعنوان السيرفر المستهلك.
- **خريطة الشبكة**: عرض بصري واحد — سيرفرات ← مواقع ← منافذ ← من يستهلك من، مع حالة كل رابط (متصل / محجوب / بطيء) من فحص `link_check` الدوري.

## 5. الواجهة

- `/servers`: تبويبات — نظرة عامة، التشغيل، المنافذ (موجود)، قواعد البيانات، التخزين، الشبكة.
- بطاقة أعلى: مواقع تعمل / متوقفة، روابط خدمات نشطة، حالة المزامنة، تنبيهات.
- `/network`: الخريطة البصرية الشاملة.

## تفاصيل تقنية

- جداول جديدة: `site_databases`, `storage_events` + أعمدة مزامنة على `site_cluster_members` و`storages` — جميعها مع RLS عبر `can_manage(owner_id)` و GRANTs.
- أوامر وكيل مضافة للقائمة البيضاء: `site_start/stop/restart/logs`, `unit_write`, `db_create`, `db_user_grant`, `db_ping`, `watch_start`, `watch_stop`, `sync_now`.
- سكربت الوكيل يرتقي إلى v2.4.0: وحدة مراقبة الملفات، تنفيذ أوامر التشغيل، وقراءة ملفات `.tvcc/site.json` للتعرّف على المواقع المملوكة.
- كل العمليات عبر `createServerFn` مع `requireSupabaseAuth` + Dry Run + تسجيل في `operation_log`.
- أدوات MCP إضافية: `list_service_links`, `start_site`, `sync_site_now`.

## خارج النطاق الآن

WireGuard/VPN بين السيرفرات، موازنة الأحمال التلقائية، وتوسيع المخزون تلقائياً.
