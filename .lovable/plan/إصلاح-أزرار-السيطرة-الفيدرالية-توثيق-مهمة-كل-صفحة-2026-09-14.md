# إصلاح أزرار «السيطرة الفيدرالية» + توثيق مهمة كل صفحة

## المشكلة المؤكدة

الملف `src/routes/_authenticated/federated.tsx` أصبح **صفحة أب** لكل الصفحات الفرعية (fleet, sql, mesh, pitr, healing, assets, db, agents)، لكنه يعرض محتوى «النظرة العامة» ولا يحتوي `<Outlet />`.
النتيجة: أي زر تضغطه داخل القسم يعرض نفس صفحة النظرة العامة. هذا ثابت من شجرة المسارات المولّدة (`FederatedRouteWithChildren`) ومن أول 20 سطر من الملف.

## الإصلاح

1. تحويل `federated.tsx` إلى غلاف بسيط يعرض `<Outlet />` فقط.
2. إنشاء `federated.index.tsx` ونقل محتوى النظرة العامة إليه كما هو (المسار `/federated` يبقى يعمل).
3. مراجعة كل صفحة من الثماني للتأكد أن مكوّنها ومسارها متطابقان، وأن كل رابط في الشريط الجانبي يفتح صفحته الصحيحة.
4. التحقق الفعلي بالمتصفح: التنقل بين الأزرار التسعة والتأكد أن العنوان والمحتوى يتغيّران، مع لقطة لكل صفحة.

## مهمة كل صفحة (تفصيل)

| الزر | المسار | المهمة |
|---|---|---|
| نظرة عامة فيدرالية | `/federated` | مؤشرات حية: عدد المواقع والسيرفرات، متوسط المعالج/الذاكرة/القرص، طبولوجيا مختصرة، والتنبيهات غير المعالَجة. تحديث كل 15 ثانية. |
| المواقع والأسطول | `/federated/fleet` | جدول كل المواقع مع بحث، استنساخ موقع، تعريف «القالب الأم» ونشره جماعياً، وسجل النشر والاستنساخ لكل موقع (نجاح/فشل/تراجع). |
| استوديو SQL | `/federated/sql` | تنفيذ استعلام واحد على عدة قواعد دفعة واحدة، تشغيل تجريبي (Dry Run)، كشف الأوامر المدمّرة وطلب تأكيد صريح، وسجل كامل للاستعلامات. |
| المزامنة والأمان | `/federated/mesh` | البث اللحظي بين المواقع، الخزنة والأسرار، جدار الحماية وقنوات الربط بين السيرفرات. |
| النسخ والسفر عبر الزمن | `/federated/pitr` | جدولة النسخ، الاستعادة إلى نقطة زمنية عبر أمر الوكيل `pitr_restore`، وربط مراكز النسخ والاسترجاع. |
| الشفاء الذاتي والسجلات | `/federated/healing` | مراقبة الأعطال، قواعد الإصلاح التلقائي، وسجل الأحداث الموحّد. |
| الأصول المركزية | `/federated/assets` | مستودع وسائط موحّد وسياسات التخزين المؤقت لكل موقع. |
| قواعد البيانات | `/federated/db` | لوحة على نمط طبقة التحكم/طبقة البيانات: المشاريع، محرر الجداول، محرر SQL، المصادقة، التخزين، الدوال، Realtime، المستشارون، المراقبة، التكاملات، الإعدادات. |
| الوكيل | `/federated/agents` | حالة وكيل كل سيرفر مباشرة، عملياته الجارية، إعدادات الوكيل، تحرير ملفات Nginx مع فحص قبل التطبيق وتراجع عند الفشل، ونسختان لكل موقع (الجديدة والقديمة) مع زر استعادة. |

## ملاحظات تقنية

- التنفيذ الفعلي على السيرفرات يمر عبر TVCC Agent فقط — لا اتصال مباشر من المتصفح بقواعد بيانات المواقع.
- الصفحات محصورة بدور المالك والمدير عبر سياسات RLS والحارس الحالي.
- لا تغيير في قواعد البيانات في هذه الدفعة؛ الجداول الثمانية أُنشئت سابقاً.
