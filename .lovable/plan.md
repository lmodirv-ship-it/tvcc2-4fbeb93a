# خطة تطوير أقسام مركز قواعد البيانات + الأدوار والعلاقات + تهجير 240+ موقعاً

الهدف: خطة منظّمة تطوّر كل قسم من أقسام مركز قواعد البيانات ليعمل فعلياً على مواقعي وقواعدها وسيرفراتها، مع الأدوار والصلاحيات والعلاقات، وتجهيز المنصة لتهجير واستضافة أكثر من 240 موقعاً. لا حذف لأي جدول أو بيانات، ويمكن إضافة صفحات جديدة عند الحاجة.

## أولاً: تطوير كل قسم داخل مركز قواعد البيانات

| القسم | ما يصبح عليه بعد التطوير |
| --- | --- |
| **نظرة عامة** | بطاقة صحّة لكل قاعدة: الحجم، عدد الجداول، آخر نسخة احتياطية، حالة الوكيل، المواقع المرتبطة، وتنبيهات فورية للنقص. |
| **محرر الجداول** | (مكتمل) يبقى كما هو مع صيانة الأداء عند كثرة الجداول. |
| **نماذج الجداول** | تطبيق نموذج على عدة مواقع دفعة واحدة، معاينة الفروقات قبل التنفيذ، وتخطّي الموجود. |
| **محرر SQL** | تشغيل الاستعلام على عدة قواعد مختارة، حفظ استعلامات مسماة، جدولة استعلام دوري، وسجل نتائج. |
| **المخطط والعلاقات** | رسم بصري للجداول والمفاتيح الأجنبية، اكتشاف العلاقات الناقصة، وتصدير المخطط. |
| **المصادقة** | عرض مستخدمي كل موقع، حالاتهم، آخر دخول، إعادة تعيين كلمة سر، وتعطيل حساب. |
| **التخزين** | حاويات التخزين لكل موقع، الحجم المستهلك، الحصص، وتنظيف الملفات اليتيمة. |
| **الدوال** | قائمة دوال ومحفّزات كل قاعدة مع نصّها، وحالة التشغيل، وتحرير آمن بموافقة. |
| **Realtime** | الجداول المفعّل عليها البث، تفعيل/تعطيل، وعدد المشتركين الحاليين. |
| **المستشارون** | فحص أمان وأداء لكل قاعدة (RLS ناقص، فهارس مفقودة، جداول بلا مفتاح) مع إصلاح مقترح بضغطة. |
| **المراقبة** | رسوم استهلاك CPU/ذاكرة/قرص واتصالات لكل قاعدة، وتاريخ ساعي، وتنبيه عند العتبات. |
| **الاتصالات** | سلاسل الاتصال وحالة كل اتصال، اختبار الاتصال الآن، وعدد الجلسات المفتوحة. |
| **النسخ والاستعادة** | جدولة نسخ لكل موقع، قائمة النسخ وأحجامها، استعادة إلى نقطة زمنية بتأكيد مزدوج. |
| **المزامنة** | مزامنة بنية أو بيانات بين قاعدتين، اتجاه المزامنة، معاينة الفروقات، وسجل تشغيل. |
| **الأسرار والمفاتيح** | خزنة لكل موقع، إظهار مؤقت، تدوير مفتاح، وسجل من وصل إليه ومتى. |
| **الاستيراد والتصدير** | استيراد/تصدير CSV وSQL لجداول أو قاعدة كاملة، مع عمل في الخلفية وتقرير نتيجة. |
| **مساعد SQL** | مساعد عربي يحوّل الطلب إلى استعلام، يشرحه، ولا ينفّذه إلا بموافقة صريحة. |
| **سجل النشاط** | كل عملية: من، ماذا، على أي قاعدة، متى، والنتيجة — مع بحث وتصفية وتصدير. |
| **الصحة والحدود** | الحدود المضبوطة لكل قاعدة (حجم، اتصالات، استعلامات بطيئة) وتحذير قبل بلوغها. |
| **هوية المواقع** | ربط كل قاعدة برمز موقعها `S######` واسمه ونطاقه، وكشف القواعد بلا هوية. |
| **الإعدادات** | إعدادات كل قاعدة: المنطقة الزمنية، الترميز، سياسة النسخ، ومستوى الوصول الافتراضي. |

كل قسم يلتزم بـ: صلاحية مطلوبة واضحة، حالة تحميل، رسالة عربية عند الفشل، تأكيد للعمليات الخطرة، وتسجيل في سجل النشاط.

## ثانياً: الأدوار والصلاحيات والعلاقات

- **`/users`**: مصفوفة صلاحيات واضحة + تبويب «صلاحيات لكل موقع» + تبويب «صلاحيات السيرفرات وقواعد البيانات».
- **`/topology`**: سلسلة كل موقع (`الموقع ← القاعدة ← السيرفر ← الوكلاء ← النطاق/الشهادة ← التخزين ← النسخ ← التنبيهات`)، جدول شامل ✓/✗، تصفية «الناقص فقط»، وزر «ربط الآن».
- **`/websites`**: عمود «الارتباط» المختصر لكل موقع مع انتقال مباشر إلى خريطة العلاقات.

## ثالثاً: تهجير قواعد بيانات 240+ موقعاً

- **جرد واكتشاف**: الوكيل يكتشف كل قاعدة على كل سيرفر (النوع، الحجم، الجداول، الترميز) ويربطها بموقعها.
- **أفواج تهجير**: مجموعات 10–20 موقعاً بالتوازي، ولكل موقع خمس مراحل: فحص مسبق → نسخة احتياطية → نقل → تحقق → تحويل الاتصال.
- **أمان**: لا نقل بلا نسخة ناجحة؛ تحقق بمطابقة عدد الجداول والصفوف؛ أي اختلاف يوقف الفوج؛ تراجع بضغطة؛ وضع تجربة بلا تنفيذ.
- **حجم**: طابور بحدود تزامن، إعادة محاولة، مهلة لكل مرحلة، لوحة تقدم حيّة، قوائم بصفحات من الخادم، وتقرير CSV نهائي.

## ترتيب التنفيذ

1. الأساس: الصلاحيات لكل قسم + سجل النشاط الموحّد + العلاقات الشاملة.
2. أقسام القراءة: نظرة عامة، المخطط، المراقبة، الاتصالات، الصحة والحدود، هوية المواقع، المستشارون.
3. أقسام التشغيل: النسخ والاستعادة، المزامنة، الاستيراد والتصدير، الدوال، Realtime، التخزين، المصادقة، الأسرار.
4. الذكاء: مساعد SQL ومحرر SQL متعدد القواعد.
5. التهجير الجماعي لـ240+ موقعاً.

## تفاصيل تقنية

- تعديل الملفات القائمة وإضافة صفحات/مكوّنات جديدة عند الحاجة: `src/routes/_authenticated/federated.db.tsx`, `users.tsx`, `topology.tsx`, `websites.tsx`، ومكوّنات `src/components/dbstudio/`.
- إعادة استخدام `src/lib/permissions.ts`, `use-permissions`, `RoleGate` بلا تغيير في الأدوار الأربعة.
- الصلاحيات الدقيقة عبر `site_user_access`, `site_users`, `user_roles`, `server_access` الموجودة.
- العلاقات: توسيع منطق `getEntityRelations` ليشمل كل المواقع دفعة واحدة.
- القواعد الخارجية عبر أوامر الوكيل الموقّعة الحالية، والقاعدة الداخلية `tvcc-hn-groupe` مباشرةً.
- هجرة واحدة (إضافة فقط) لجداول أفواج التهجير ومهامه وسجل النشاط الموحّد، مع GRANT وسياسات RLS كاملة وفهارس على الموقع والحالة.
- كل دوال الكتابة محميّة بـ`requireSupabaseAuth` + فحص الدور في `src/lib/roles.server.ts`.
- مساعد SQL عبر بوابة الذكاء الاصطناعي في Lovable دون مفاتيح إضافية.
