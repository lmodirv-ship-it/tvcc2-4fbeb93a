# محرر جداول كامل داخل مركز قواعد البيانات

الهدف: أن يصبح تبويب «محرر الجداول» في TVCC بديلاً كاملاً عن محرر جداول سوبابيز المحلي الظاهر في الصور — وأقوى منه — مع بقاء كل التنفيذ عبر وكيل TVCC الموقّع (لا اتصال مباشر بالقاعدة).

## ما سيراه المستخدم

### 1) شريط جانبي للجداول (يسار/يمين حسب الاتجاه)
- اختيار المخطط (public, auth, storage, vault, realtime…) من قائمة منسدلة مع بحث.
- قائمة جداول المخطط مع بحث فوري، وعلامة لكل جدول: مُقيّد بـ RLS أو «غير محمي» (تحذير أحمر مثل UNRESTRICTED).
- نوع الكائن: جدول / عرض (view) / جدول أجنبي، مع عدد الصفوف والحجم.

### 2) شبكة البيانات (Data Grid)
- عرض الصفوف في جدول أفقي قابل للتمرير، رأس كل عمود يعرض الاسم + نوع البيانات + مفتاح أساسي/أجنبي.
- ترقيم الصفحات (100 صف افتراضياً، قابل للتغيير) مع «عدد السجلات الكلي».
- ترتيب حسب أي عمود، وفلترة (`عمود = قيمة`, `يحتوي`, `فارغ`…) مع إمكانية جمع أكثر من شرط.
- إخفاء/إظهار الأعمدة وتثبيت العمود الأول.
- تحديد صفوف بمربعات اختيار، وتوسيع أي صف في لوحة جانبية لقراءة القيم الطويلة و JSON بشكل مرتب.

### 3) التحرير (مع حماية)
- تعديل خلية بالنقر المزدوج، إضافة صف، حذف صفوف محددة، نسخ صف.
- كل التعديلات تدخل «طابور تغييرات» (Queue) يظهر ما سيتغير قبل الحفظ — لا حفظ تلقائي.
- زر «حفظ» يطلب تأكيداً صريحاً، ثم يُرسل الأمر إلى الوكيل ويُسجَّل في السجل الأمني وسجل التدقيق.
- الحذف والتعديل الجماعي يتطلب كتابة «تأكيد».

### 4) إدارة بنية الجدول
- إنشاء جدول جديد بنافذة مطابقة لما في الصورة: الاسم، الوصف، تفعيل RLS (مفعّل افتراضياً)، تفعيل Realtime، والأعمدة (اسم/نوع/قيمة افتراضية/مفتاح أساسي/علاقة أجنبية).
- إضافة عمود، تعديل نوع/قيمة افتراضية، حذف عمود، إعادة تسمية، إنشاء فهرس.
- استيراد بيانات من CSV، وتصدير الجدول أو نتيجة الفلترة إلى CSV/JSON.

### 5) سياسات RLS والصلاحيات
- تبويب لكل جدول يعرض سياساته الحالية ومن يستطيع القراءة/الكتابة.
- إنشاء سياسة من قوالب جاهزة (مالك الصف فقط · مدير فقط · قراءة عامة) بدل كتابة SQL يدوياً.
- تحذير واضح لأي جدول بلا RLS أو بلا GRANT.

### 6) إضافات تتجاوز سوبابيز
- تعدد القواعد: نفس المحرر يعمل على أي قاعدة مربوطة (محلية على 192.168.100.66 أو سحابية) باختيار واحد من الأعلى.
- مقارنة مخطط قاعدتين وإظهار الفروقات مع توليد SQL المزامنة.
- لقطة سريعة قبل أي تعديل بنيوي، مع زر تراجع.
- سجل «من غيّر ماذا ومتى» لكل جدول.
- مفضّلة للجداول كثيرة الاستخدام، وفتح تبويبات متعددة للجداول مثل الصورة.

## التفاصيل التقنية

- طبقة البيانات: أوامر الوكيل الموجودة `pg_meta`, `pg_rows`, `pg_write`, `db_query`, `db_policy`, `db_export`, `db_import_full` في `src/lib/dbstudio.functions.ts`؛ تُضاف أوامر `pg_ddl` (إنشاء/تعديل جدول وعمود وفهرس) و`pg_import_csv` إلى قائمة `DB_ACTIONS` المسموح بها.
- دوال خادم جديدة في `src/lib/dbstudio.functions.ts`: `listSchemas`, `listTables`, `readRows` (مع pagination/sort/filters)، `writeRows`، `applyDdl`، `managePolicies` — كلها خلف `requireSupabaseAuth` + `isAdminOrOwner`، مع تسجيل في `audit_log` و`security_events`.
- منع SQL الخطر: يُبنى SQL على الخادم من مدخلات محقّقة (أسماء مخطط/جدول/عمود من قوائم فعلية) بدل تمرير نص المستخدم؛ نص SQL الحر يبقى في تبويب SQL الحالي بقواعده.
- الواجهة: مكوّنات جديدة تحت `src/components/dbstudio/` (`TableSidebar`, `DataGrid`, `RowDrawer`, `NewTableDialog`, `ColumnDialog`, `PolicyPanel`, `ChangeQueue`) يستوردها تبويب «محرر الجداول» في `src/routes/_authenticated/federated.db.tsx` بدل اللوحة العامة الحالية.
- النتائج تُقرأ من مخرجات أوامر الوكيل الحالية (`server_commands.output`) مع مؤشر «بانتظار الوكيل» و«آخر قراءة قبل X».
- لا تغيير في بقية التبويبات ولا في نموذج الصلاحيات.

## التنفيذ على مراحل

1. الشريط الجانبي للمخططات/الجداول + شبكة البيانات للقراءة (فلترة، ترتيب، صفحات، تصدير).
2. التحرير: طابور التغييرات، حفظ مؤكَّد، إضافة/حذف صفوف، لوحة الصف.
3. البنية: إنشاء جدول/عمود/فهرس، استيراد CSV.
4. سياسات RLS والقوالب والتحذيرات.
5. الإضافات: مقارنة المخططات، اللقطات والتراجع، المفضلة والتبويبات.
