# تطوير: مركز المنافذ، الأدوار، وتشغيل النماذج المحلية

ثلاثة محاور: صفحة السيرفرات تصبح مركز إدارة منافذ حقيقي، صفحة المستخدمين تمنح المدير صلاحيات المالك، ونماذج الذكاء المحلية تُشغَّل وتُربط بمنافذ السيرفرات.

## 1. إدارة المنافذ (صفحة السيرفرات)

اليوم تبويب «المنافذ» يعرض ما يرصده الوكيل وزر واحد «ربط بموقع». يُوسَّع إلى مركز كامل:

- **حالة المنفذ وتشغيله**: لكل منفذ حالة (مفتوح / مغلق / محجوب بالجدار الناري) مع أزرار: فتح/إغلاق في الجدار الناري (`ufw`)، اختبار الوصول من الخارج، وإعادة تشغيل الخدمة المرتبطة.
- **إضافة منفذ يدوياً**: تسجيل منفذ يعرفه المستخدم ولم يرصده الوكيل بعد (رقم، بروتوكول، وصف، نوع الخدمة).
- **ربط منفذ ← موقع**: يبقى الموجود (خدمة + بروكسي Nginx) مع معاينة البلوك قبل التنفيذ ودعم Dry Run، وإضافة خيار مسار فرعي (`/api` مثلاً) بدل النطاق كامل، وخيار WebSocket، وطلب شهادة SSL بعد نجاح البروكسي.
- **ربط منفذ ← منفذ (Port ↔ Port)**: جديد. جدول `port_links` يربط منفذاً على سيرفر A بمنفذ على سيرفر B (نوع الجسر: TCP forward / reverse proxy / نفق SSH)، مع فحص وصول دوري وحالة الرابط. التنفيذ عبر أوامر جديدة في الوكيل ضمن القائمة البيضاء.
- **كتالوج الخدمات الجاهزة**: قوالب لتشغيل خدمة على منفذ بضغطة (Ollama 11434، PostgreSQL 5432، Redis 6379، n8n 5678، MinIO 9000، Nginx 80/443) — كل قالب يولّد أمر الوكيل + يسجّل الخدمة في `site_services` تلقائياً.
- **خريطة المنافذ**: عرض بصري: سيرفر ← منافذه ← الموقع/الخدمة المستهلِكة ← الروابط بين السيرفرات.
- كل عملية تُسجَّل في `operation_log` وتدعم Dry Run.

## 2. الأدوار: المدير = المالك

اليوم بيانات السيرفرات والمواقع والعملاء والخزنة مقيّدة بالمالك الفعلي فقط، فالمستخدم بدور Admin لا يرى شيئاً.

- إضافة دالة قاعدة بيانات `can_manage(owner_id)`: تُرجع صحيح إذا كان المستخدم هو المالك، أو مالك النظام، أو يحمل دور `admin` ومنحه إياه مالك النظام.
- تحديث سياسات RLS للجداول التشغيلية (المواقع، السيرفرات، المنافذ، الخدمات، النماذج، المجموعات، النطاقات، الشهادات، العملاء، الاشتراكات) لتستخدم هذه الدالة — فيرى المدير كل ما يراه المالك ويعدّله.
- **يبقى محصوراً بمالك النظام**: حذف المواقع الـ188، قراءة قيم الخزنة `vault_secrets` بصريح النص، إدارة الأدوار، وحذف السيرفرات. المحرر (Editor) يبقى عرض + تعديل بلا حذف.
- **حساب `lmodirv@gmail.com`** يبقى محمياً كما هو: لا يُحذف ولا تُغيَّر صلاحياته (المشغّلات في القاعدة قائمة).
- في الواجهة: صفحة المستخدمين تعرض مصفوفة صلاحيات واضحة لكل دور، وأزرار الحذف تُخفى لغير المخوَّل.

ملاحظة: هذا يوسّع الوصول عمداً لفريقك — سيُسجَّل في مذكرة الأمان حتى لا يُعاد الإبلاغ عنه كثغرة.

## 3. النماذج المحلية والربط بالمنافذ (صفحة الربط)

- **اكتشاف تلقائي عبر المنافذ**: زر «فحص نماذج السيرفر» يبحث في `server_ports` عن منافذ النماذج المعروفة (11434 Ollama، 1234 LM Studio، 8000 vLLM، 8080 llama.cpp)، ويستدعي الوكيل لجلب قائمة النماذج وتسجيلها كمزوّد + نماذج.
- **تشغيل/إيقاف النموذج المحلي**: أزرار Start / Stop / Pull / Remove تُنفَّذ عبر الوكيل (`ollama serve`, `ollama pull`, `systemctl`), مع عرض الحالة الحية وحجم النموذج.
- **ربط النموذج بمنفذ**: عمود `port` + `server_port_id` على `ai_models` لربط كل نموذج بالمنفذ الذي يخدمه، وزر «نشر النموذج على نطاق» يعيد استخدام بروكسي المنفذ لجعل النموذج متاحاً على `ai.<domain>` بمفتاح وصول.
- **نماذج حاسوبك المحلي** تبقى تُستدعى من المتصفح مباشرة، مع فحص اتصال وتعليمات CORS.
- **بطاقة حالة موحدة** لكل مصدر (سحابي / حاسوب / سيرفر): متصل، زمن الاستجابة، عدد النماذج، المنفذ، آخر اختبار.

## تفاصيل تقنية

- جداول/أعمدة جديدة: `port_links`، أعمدة `state`/`managed`/`service_kind` على `server_ports`، `server_port_id` + `port` على `ai_models` — مع RLS عبر `can_manage()` و GRANTs.
- أوامر جديدة في القائمة البيضاء للوكيل: `firewall_open`, `firewall_close`, `port_check`, `port_forward`, `service_restart`, `ollama_pull`, `ollama_rm`, `ollama_ps`.
- كل الاستدعاءات عبر `createServerFn` مع `requireSupabaseAuth`، وتُسجَّل في `operation_log`، مع دعم Dry Run الحالي.
- توسيع أدوات MCP بـ `list_ports` و `link_port`.

## خارج النطاق الآن

WireGuard/VPN بين السيرفرات، وموازنة الأحمال التلقائية للنماذج.
