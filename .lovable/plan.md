# صفحة خاصة لكل سيرفر + ربط المنافذ + وكيل ذكي كل دقيقة

حالياً تفاصيل السيرفر تُعرض داخل نافذة منبثقة في `/servers` بستة تبويبات، والوكيل الحالي v3.2.0 يرسل نبضة كل 180 ثانية ويسجّل تغيّر عنوان IP في `server_ip_history`. الخطة تحوّل ذلك إلى صفحة مستقلة كاملة، وتضيف أدوات الربط المطلوبة، وترفع الوكيل إلى v3.3.0.

## 1. صفحة مستقلة لكل سيرفر

مسار جديد `/servers/{id}` — الضغط على أي بطاقة سيرفر ينقل إليها بدل النافذة المنبثقة (تبقى النافذة السريعة اختيارية للعرض المختصر).

محتوى الصفحة:

- **شريط علوي**: اسم السيرفر، الحالة (متصل/متأخر/متوقف)، عنوان IP العام والخاص، مزوّد الخدمة، إصدار الوكيل، آخر نبضة، وزر رجوع.
- **بطاقات الموارد**: المعالج (نسبة الاستخدام + عدد الأنوية + معدل الحمل)، الذاكرة (مستخدم/إجمالي)، القرص (مستخدم/إجمالي + مساحة متبقية)، زمن التشغيل، عدد العمليات — مع رسوم بيانية زمنية لآخر 24 ساعة.
- **التخزين**: الأقراص والأقسام المكتشفة ومساحة كل موقع.
- **المنافذ المفتوحة**: جدول (المنفذ، البروتوكول، الخدمة، العملية، عام/محلي، الحالة) مع فحص منفذ وفتح/إغلاق عبر الجدار الناري.
- **التبويبات الحالية** (التشغيل، الإعدادات، الأدوات، الترحيل، المواقع، السجلات) منقولة كما هي داخل الصفحة الجديدة.
- **سجل تغيّر عناوين IP** لهذا السيرفر.

## 2. أزرار الربط الثلاثة (في تبويب المنافذ)

1. **ربط منفذ باسم نطاق**: اختيار منفذ + نطاق (من نطاقات المنصة أو نطاق ‎.HN‎) ⇒ الوكيل يكتب بلوك Nginx عكسي (proxy_pass إلى المنفذ)، يصدر شهادة SSL، ويسجّل الربط. حالة الربط تظهر في الجدول مع زر فحص وإلغاء.
2. **ربط منفذ بـ Supabase CLI**: نموذج يستقبل عنوان Supabase الذاتي (مثل `http://192.168.100.66:8000`) ومفاتيحه ⇒ يُخزَّن المفتاح مشفّراً في الخزنة، يُنشأ جسر منفذ محلي على السيرفر نحو الخدمة، ويُحقن `SUPABASE_URL`/`SUPABASE_ANON_KEY` في متغيرات بيئة الموقع المختار، مع زر فحص اتصال فعلي.
3. **ربط منفذ بخدمة على منفذ آخر**: توسيع جسور `port_links` الحالية لتشمل الربط بين سيرفرين أو بين موقع وخدمة داخلية — اختيار المصدر (سيرفر+منفذ) والوجهة، مع فحص دوري للحالة (متصل/محجوب/بطيء).

جميع العمليات تدعم المحاكاة (Dry Run) وتُسجَّل في `operation_log`.

## 3. ترقية الوكيل إلى v3.3.0

- **الفاصل الزمني**: نبضة كل **60 ثانية** بدل 180 (قابل للضبط عبر `TVCC_HEARTBEAT_INTERVAL`).
- **إعادة الاتصال عند تغيّر IP**: الوكيل يقارن IP الحالي بالمخزَّن محلياً؛ عند أي تغيير يرسل نبضة فورية بعلامة `ip_changed` مع العنوانين القديم والجديد، والمنصة تحدّث `servers.hostname`/`public_ip` تلقائياً وتسجّل الحدث وترسل تنبيهاً.
- **الاتصال عند الإقلاع**: وحدة systemd (`tvcc-agent.service`) بتفعيل تلقائي عند الإقلاع وإعادة تشغيل عند الفشل، مع نبضة أولى فورية عند البدء.
- **بيانات إضافية في النبضة**: تفاصيل الأنوية والذاكرة الحقيقية بالبايت، الأقراص والأقسام، بطاقات الشبكة وعناوينها، المنافذ المستمعة مع اسم العملية، الخدمات النشطة، الحاويات، وحالة الجسور المفتوحة.

## تفاصيل تقنية

- مسار جديد `src/routes/_authenticated/servers.$serverId.tsx`؛ `servers.tsx` يصبح قائمة تنقل إليه.
- استخدام الجداول الموجودة: `server_metrics`, `server_ports`, `server_disks`, `server_net_interfaces`, `server_services`, `server_containers`, `server_ip_history`, `port_links`.
- ترحيل (migration) بسيط: أعمدة ربط النطاق وSupabase على `port_links` (`link_kind`, `domain`, `target_url`, `vault_secret_id`) مع GRANT وسياسات RLS عبر `can_manage(owner_id)`.
- أوامر وكيل جديدة في القائمة البيضاء: `domain_bind`, `supabase_link`, `bridge_create`, `bridge_drop`, `net_report`.
- كل الاستدعاءات عبر `createServerFn` مع `requireSupabaseAuth`.
- **VPN بين السيرفرات (ضمن النطاق)**: نفق WireGuard مُدار من اللوحة — توليد مفاتيح لكل سيرفر وتخزينها مشفّرة في الخزنة، تركيب الواجهة عبر الوكيل (`vpn_setup`, `vpn_peer_add`, `vpn_status`)، وعناوين داخلية ثابتة تصبح الوجهة الافتراضية لجسور المنافذ بدل الإنترنت.
