# إدارة المواقع من السيرفرات (VPS) — الحالة والموارد

إضافة طبقة «سيرفرات» للوحة TVCC: تسجيل عدة سيرفرات VPS، ربط كل موقع بسيرفره، وعرض حالة السيرفر وموارده (CPU / RAM / القرص / Uptime) مع حالة كل موقع عليه.

## ملاحظة تقنية مهمة

خادم التطبيق يعمل على بيئة Workers ولا يستطيع فتح اتصال SSH مباشر بالسيرفرات. لذلك الحل العملي والآمن هو **وكيل خفيف (Agent)** يُثبَّت على كل VPS ويرسل القراءات دورياً إلى نقطة استقبال في اللوحة، ويعمل نفس الوكيل كجسر لنماذج الذكاء الاصطناعي المحلية المثبّتة على السيرفر (Ollama / llama.cpp / vLLM). النتيجة على الشاشة نفسها المطلوبة (حالة وموارد لحظية لكل سيرفر وموقع)، لكن الاتجاه push بدل SSH — وهو أيضاً أأمن لأنه لا يتطلب تخزين مفاتيح SSH.

### إضافة: نماذج الذكاء الاصطناعي وأدوات إدارة وتطوير المواقع

- **جدول `ai_providers`**: المزوّد (Lovable AI / OpenAI / OpenRouter / Anthropic / Google / Ollama / llama.cpp / vLLM / LM Studio / مخصّص متوافق مع OpenAI)، النوع (سحابي / محلي / على سيرفر)، رابط الـBase URL، مفتاح مشفّر (اختياري للمحلي)، الحالة، `server_id` عند الحاجة — مع RLS و GRANTs.
- **جدول `ai_models`**: مرتبط بالمزوّد — اسم النموذج، النوع (`cloud` عبر Lovable AI / `local` على جهاز المستخدم-اللوحة / `server` على أحد سيرفرات VPS)، معرّف النموذج، `server_id` عند الحاجة، رابط النهاية، مفتاح مشفّر، الحالة (مفعّل/متوقف)، القدرات (نص/صور/أدوات)، حجم السياق، الأولوية — مع RLS و GRANTs.
- **النماذج المحلية**: اكتشاف تلقائي لقائمة النماذج من كل مزوّد محلي (`/api/tags` لـOllama و`/v1/models` للمتوافق مع OpenAI) عبر الوكيل، مع عرض حجم النموذج وحالة التحميل، وإمكانية سحب نموذج جديد (`pull`) وحذفه من داخل اللوحة.
- **صفحة `/ai-models` (تفعيل النماذج)**: إضافة نموذج، اكتشاف النماذج المحلية تلقائياً من الوكيل على كل سيرفر، اختبار الاتصال (زمن الاستجابة)، تفعيل/تعطيل، تحديد النموذج الافتراضي، ومراقبة الاستهلاك.
- **صفحة `/ai-chat` (التواصل مع النماذج)**: محادثة متدفّقة مع اختيار النموذج والسيرفر، سياق المواقع المحدّدة، وسجل المحادثات في جدول `ai_conversations` / `ai_messages`.
- **أدوات إدارة وتطوير المواقع (Tool calling)**: تُستدعى من داخل المحادثة وتُعرض للنماذج وأيضاً كأدوات MCP — قراءة/تعديل بيانات موقع، فحص الحالة والموارد، فحص DNS/SSL، توليد وتحرير محتوى وSEO، تعديل جماعي على مجموعة مواقع، إنشاء مهام نشر، وقراءة سجلات السيرفر. كل أداة تُنفَّذ عبر `createServerFn` بهوية المستخدم (RLS محفوظة) وتتطلب تأكيداً صريحاً قبل أي عملية تعديل أو حذف.
- **التوجيه**: النماذج السحابية عبر Lovable AI Gateway بدون مفاتيح، ونماذج السيرفر عبر الوكيل (نداء موقّع HMAC) دون فتح منافذ النماذج للإنترنت، مع تراجع تلقائي إلى النموذج الافتراضي عند تعذّر الوصول.

## ما سيُبنى

### 1. قاعدة البيانات
- جدول `servers`: الاسم، الوصف، عنوان IP/hostname، المزوّد، المنطقة، المواصفات (vCPU، RAM، Disk)، الحالة (online/offline/warning)، `agent_token_hash`، `last_seen_at`، `owner_id` + RLS + GRANTs.
- جدول `server_metrics`: قراءات دورية (cpu_percent، mem_used/total، disk_used/total، load_avg، uptime_seconds، عدد العمليات، `collected_at`) للرسوم البيانية والتاريخ.
- عمود `server_id` في جدول `websites` لربط كل موقع بسيرفره.
- جدول `server_sites`: ما يراه الوكيل فعلياً على السيرفر (اسم الموقع/الخدمة، الحالة، المنفذ) لمطابقته مع مواقع اللوحة.

### 2. نقطة استقبال عامة للوكيل
`POST /api/public/servers/heartbeat` — نفس نمط نقاط الاستقبال الحالية في المشروع (توقيع HMAC-SHA256 على الجسم الخام + مقارنة زمنية آمنة، تحقق من صحة الحقول قبل الكتابة). تستقبل قراءة كل دقيقة، تحدّث `servers.status/last_seen_at` وتُدرج صفاً في `server_metrics`، وتُعلّم السيرفر offline تلقائياً إذا انقطعت النبضات.

### 3. سكربت الوكيل
سكربت Bash/Node جاهز للنسخ من داخل اللوحة، يُثبَّت على الـVPS كخدمة systemd أو مهمة cron، يقرأ الموارد من النظام ويرسلها موقّعة بمفتاح السيرفر.

### 4. الواجهة
- صفحة جديدة `/servers` (رابط في القائمة الجانبية + ترجمات ar/en/fr):
  - بطاقات إحصائية: عدد السيرفرات، المتصلة، تحذيرات، متوسط الاستهلاك.
  - جدول السيرفرات: الحالة، آخر اتصال، أشرطة CPU/RAM/Disk، عدد المواقع المستضافة.
  - إضافة/تعديل/حذف سيرفر + توليد مفتاح الوكيل وعرض أمر التثبيت مرة واحدة.
- صفحة تفاصيل السيرفر: رسم بياني للموارد آخر 24 ساعة + قائمة المواقع المرتبطة بحالة كل منها.
- في صفحة المواقع: عمود/حقل «السيرفر» لاختيار السيرفر المستضيف.

### 5. أدوات MCP
`list_servers` و `get_server_status` لتتمكن الوكلاء الذكية من قراءة حالة السيرفرات.

## تفاصيل تقنية
- الأسرار: `SERVERS_INGEST_SECRET` لتوقيع النبضات؛ مفتاح كل وكيل يُخزَّن مُجزّأً (hash) فقط.
- قراءات اللوحة عبر `createServerFn` مع `requireSupabaseAuth`؛ الصفحات تحت `_authenticated/`.
- تنظيف دوري لـ `server_metrics` (الاحتفاظ بـ7 أيام تفصيلية).
