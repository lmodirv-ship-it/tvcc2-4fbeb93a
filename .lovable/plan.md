# نظام السيطرة الفيدرالية (Federated Control)

قسم جديد في القائمة الجانبية يوضع **فوق قسم الذكاء الاصطناعي**، بعنوان «نظام السيطرة الفيدرالية»، وتحته 7 أزرار = 7 صفحات لإدارة كل المواقع (245) من مكان واحد بنموذج «القالب الأم» بدل إدارة كل موقع على حدة.

## الأزرار السبعة

| # | الزر / الصفحة | المسار | المحتوى |
|---|---|---|---|
| 1 | نظرة عامة فيدرالية | `/federated` | خريطة طبولوجيا حية، مؤشرات CPU/RAM/تخزين مجمّعة، مركز التنبيهات الحرجة |
| 2 | المواقع والأسطول | `/federated/fleet` | جدول كل المواقع مع بحث وتصفية، استنساخ موقع إلى سيرفر آخر، نشر جماعي |
| 3 | استوديو قواعد البيانات | `/federated/sql` | محرر SQL جماعي (موقع / مجموعة / الكل)، محرر جداول مقارن، اقتراح فهارس |
| 4 | المزامنة والأمان المركزي | `/federated/mesh` | بث أحداث لحظي، إدارة مفاتيح الاتصال مركزياً، قواعد جدار الحماية |
| 5 | النسخ والسفر عبر الزمن | `/federated/pitr` | استعادة نقطة زمنية، جداول النسخ الاحتياطي لكل قاعدة |
| 6 | الشفاء الذاتي والسجلات | `/federated/healing` | سجلات تدقيق مركزية، بروتوكولات إعادة التشغيل الآلي |
| 7 | الأصول المركزية | `/federated/assets` | مستودع وسائط موحّد وتحكم بالتخزين المؤقت |

## القالب الأم (Master Blueprint)

بدل تكرار العمل على 245 موقعاً: يُعرَّف هيكل الجداول والعلاقات في قالب مركزي واحد، وأي تعديل عليه يُنشر كمهمة على المواقع المستهدفة عبر الوكيل الموجود، مع سجل نشر لكل موقع (نجاح / فشل / تراجع).

## زر «قواعد البيانات» (منصة خدمات فوق PostgreSQL)

زر ثامن أسفل الأزرار السبعة على المسار `/federated/db`، وصفحته مقسّمة إلى تبويبات تعكس الفصل بين طبقة التحكم وطبقة البيانات:

| التبويب | المحتوى |
|---|---|
| المشاريع (Control Plane) | إنشاء وإدارة قواعد بيانات المشاريع، الحدود والحصص، الحالة، وربطها بالمواقع والسيرفرات |
| محرر SQL | تنفيذ استعلامات على قاعدة محددة مع حماية الأوامر المدمّرة |
| محرر الجداول | استعراض وتحرير الصفوف، الأعمدة، والمفاتيح الخارجية |
| المصادقة | مستخدمو كل مشروع، مزودو الدخول، وإعدادات الرموز |
| التخزين | الحاويات والملفات المتوافقة مع S3 وصلاحياتها |
| Realtime | القنوات والجداول المفعّلة للبث اللحظي |
| الدوال | دوال الحافة لكل مشروع وسجلاتها |
| الاتصال والبوابة | روابط REST، مفاتيح الوصول، تجميع الاتصالات (Pooler)، وحدود المعدل |
| المراقبة والسجلات | الاستعلامات البطيئة، الأخطاء، الاستهلاك، وسجل التدقيق |
| الأمان | سياسات RLS، الامتدادات، والأسرار |

ما يُنفَّذ فعلياً في منصتنا: واجهة التحكم وقاعدة البيانات الوصفية للمشاريع، والتنفيذ الحقيقي على السيرفرات يمر عبر TVCC Agent (أوامر `db_provision`, `db_query`, `db_policy`, `pooler_config`). مكوّنات البنية (PostgREST، GoTrue، Kong، Supavisor، MinIO) تُركّب على السيرفر المستهدف عبر الوكيل وتُدار من هذه الصفحة، لا داخل المتصفح.

## مراحل التنفيذ


**المرحلة 1 — الأساس (هذه الدفعة)**
- جداول جديدة: `fleet_blueprints` (القوالب)، `blueprint_deployments` (سجل النشر لكل موقع)، `federated_queries` (سجل الاستعلامات الجماعية مع التأكيد)، `site_clones` (عمليات الاستنساخ)، `federated_alerts`. كلها بصلاحيات RLS للمالك/المدير فقط.
- القسم الجديد في القائمة الجانبية فوق «الذكاء الاصطناعي» + تسجيل الصفحات السبع في سجل الصفحات (`platform_pages`) ليخضع للتفعيل والأدوار.
- الصفحات السبع بهيكلها وتبويباتها، مع صفحة 1 و2 مربوطتين فعلياً بالبيانات الحالية (`servers`, `websites`, `server_metrics`, `site_databases`) عبر دالة الطبولوجيا الموجودة.

**المرحلة 2 — التشغيل**
- محرر SQL الجماعي: اختيار الهدف (موقع/مجموعة/الكل)، تشغيل تجريبي (Dry Run) إجباري، حظر الأوامر المدمّرة إلا بتأكيد نصي مطابق، وتنفيذ عبر أوامر الوكيل الموجودة.
- الاستنساخ والنشر الجماعي كمهام وكيل جديدة مع إعادة ربط مسارات القاعدة تلقائياً.
- محرر الجداول المقارن جنباً إلى جنب بين موقعين.

**المرحلة 3 — الذكاء والأمان**
- تحويل اللغة الطبيعية إلى SQL وشرح الأخطاء عبر بوابة الذكاء الاصطناعي الحالية.
- اقتراح الفهارس تلقائياً من سجل الاستعلامات البطيئة.
- خريطة علاقات تفاعلية، PITR، الشفاء الذاتي، والأصول المركزية.

## ملاحظات تقنية

- كل تنفيذ فعلي على السيرفرات يمر عبر TVCC Agent الموجود (أوامر جديدة: `blueprint_apply`, `site_clone`, `multi_sql`, `pitr_restore`) — لا اتصال مباشر من المتصفح بقواعد بيانات المواقع.
- البث اللحظي يبدأ بقنوات Realtime الحالية؛ Redis Pub/Sub خارج نطاق الاستضافة الحالية ويُستبدل بها.
- التحرير التشاركي (CRDT) وZero-Downtime Schema مؤجلان لما بعد المرحلة 3 لأنهما يتطلبان خدمة دائمة على VPS.
- كل الصفحات RTL وثلاثية اللغة مثل باقي المنصة، وتستخدم رموز التصميم الحالية.

## ما سأبدأ به فور الموافقة
المرحلة 1 كاملة: الجداول + القسم والأزرار السبعة + الصفحتان الأولى والثانية بالبيانات الحية، ثم أتابع المرحلتين 2 و3 تباعاً.
