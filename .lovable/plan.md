# تطوير صفحات السيطرة الفيدرالية — من واجهات إلى نظام تشغيل فعلي

الصفحات التسع مبنية وتعمل الآن (كل زر يفتح صفحته). المرحلة التالية: تحويلها من عرض بيانات إلى تحكم فعلي في الأسطول.

## ملاحظة على المعمارية المقترحة

المواصفة المرسلة تفترض Control Plane بلغة Go + gRPC + Temporal + Prometheus + Vault. المنصة الحالية مبنية على TanStack Start + قاعدة بيانات Lovable Cloud + وكيل TVCC (Python/Bash) يعمل على كل سيرفر ويتصل عبر HTTP.

الخطة تنفّذ **نفس الوظائف** بالمكوّنات الحالية بدل إعادة البناء:

| في المواصفة | ما سيُنفَّذ هنا |
|---|---|
| Control Plane (Go/chi) | دوال الخادم في `src/lib/federated.functions.ts` + مسارات `api/public` |
| Site Agent (gRPC) | وكيل TVCC الحالي (v3.8) عبر جدول الأوامر + نبضات HTTP |
| Temporal Workflows | جدول المهام `agent_jobs` + خطوات `agent_job_steps` مع تقدّم وتراجع |
| Prometheus/Grafana | `server_metrics` + `server_health_snapshots` + رسوم داخل المنصة |
| Vault | `vault_secrets` المشفّرة (AES-256-GCM) الموجودة |
| WireGuard mesh | `server_tunnels` + `server_vpn_peers` الموجودة |

## المراحل

### المرحلة 1 — طبقة التحكم والمهام (الأساس)
- محرّك مهام موحّد: كل عملية طويلة (استنساخ، نسخ احتياطي، استعادة، تحديث جماعي) تُنشئ مهمة بخطوات وتقدّم مئوي وسبب فشل وإمكانية إلغاء.
- تنفيذ فعلي عبر الوكيل: إضافة أوامر `site_clone`، `bulk_update`، `pitr_restore`، `sql_exec` إلى سكربت الوكيل مع إرسال تقدّم كل خطوة.
- سجل تدقيق مركزي: جدول `audit_log` يسجّل كل عملية إدارية (من، ماذا، على أي موقع، قبل/بعد).

### المرحلة 2 — النظرة العامة والطبولوجيا
- خريطة حية: عقد السيرفرات وحواف الأنفاق المشفّرة مع حالة كل نفق وزمن الاستجابة.
- مؤشرات مجمّعة للأسطول (معالج/ذاكرة/تخزين) مع اتجاه زمني.
- مركز تنبيهات بحالات: مشتعل / مُعترف به / محلول، وقواعد تنبيه قابلة للتحرير، وإشعار عبر القنوات الموجودة.
- تحديث لحظي عبر الاشتراك اللحظي بدل إعادة الطلب كل 15 ثانية.

### المرحلة 3 — المواقع والأسطول
- جدول المواقع بترقيم صفحات وفلترة وبحث على الخادم (لا تحميل 245 صفاً دفعة واحدة).
- الاستنساخ الفوري: لقطة → نقل → استعادة → إعادة ربط النطاق والمتغيّرات → تراجع عند الفشل.
- التحديث الجماعي على دفعات مع فحص صحة بعد كل دفعة وإيقاف تلقائي عند تجاوز نسبة الفشل.

### المرحلة 4 — استوديو قواعد البيانات
- تنفيذ استعلام على موقع/عدة مواقع/الشبكة كاملة بالتوازي مع مهلة ونتائج متدفّقة.
- حماية: القراءة افتراضياً، والكتابة و DDL تتطلب تأكيداً صريحاً ودور مالك/مدير.
- مقارنة جدولين بين موقعين مع تلوين الفروقات.
- الاستعلامات البطيئة واقتراح الفهارس مع أمر جاهز للموافقة.

### المرحلة 5 — النسخ والسفر عبر الزمن
- استعادة لنقطة زمنية عبر الوكيل مع تقدّم مرحلي وتحقق بعد الاستعادة.
- سياسات نسخ لكل موقع (جدولة، مدة احتفاظ، وجهة محلية وسحابية، تشفير) وفحص دوري لصلاحية النسخ.

### المرحلة 6 — الشفاء الذاتي والسجلات والأصول
- مراقب خدمات على الوكيل يعيد تشغيل ما ينهار ويسجّل الحدث ويُشعر.
- مركز سجلات موحّد بفلترة بالتاريخ والمستخدم والموقع.
- مستودع وسائط موحّد وتحكم بالتخزين المؤقت مع أمر تفريغ الكاش.

### المرحلة 7 — الوكيل والشهادات والأمان
- توجيه عكسي مُدار من القاعدة (نطاق ← موقع ← منفذ) مع تطبيق ذرّي واختبار قبل التفعيل.
- إصدار وتجديد الشهادات تلقائياً مع تنبيه قبل 30 يوماً من الانتهاء.
- قواعد جدار حماية وحظر تلقائي لمحاولات الحقن، مع سجل.

## تفاصيل تقنية

- جداول جديدة: `audit_log`، `fleet_jobs`/توسيع `agent_jobs` بخطوات وتقدّم، `alert_rules`، `query_history`. الباقي موجود (`servers`، `websites`، `server_commands`، `server_metrics`، `site_backups`، `recovery_points`، `vault_secrets`، `server_tunnels`).
- كل جدول جديد: RLS مقيّد للمالك/المدير + GRANT للأدوار المناسبة + فهارس على الحالة والتاريخ.
- لا تنفيذ مباشر من المتصفح على السيرفرات: كل أمر يمر عبر جدول الأوامر ويلتقطه الوكيل.
- البث اللحظي عبر الاشتراك اللحظي في القاعدة للجداول: التنبيهات، المهام، حالة السيرفرات.
- ترقية الوكيل إلى إصدار جديد مع الأوامر المضافة وإرسال التقدّم بدل نتيجة واحدة في النهاية.

## ما لن يُنفَّذ الآن

Go / gRPC / Temporal / Prometheus / Kafka / Kubernetes — تتطلب بنية تشغيل منفصلة خارج المنصة. وظائفها مغطّاة بالمكوّنات أعلاه. يمكن إضافتها لاحقاً كطبقة اختيارية إن أردت.

## البدء

أنفّذ المراحل السبع كاملة في هذه الجولة بالترتيب، بدءاً من المرحلة 1 (محرّك المهام + الوكيل + سجل التدقيق) لأن باقي المراحل تعتمد عليها. ويُضاف إليها ثلاثة أعمال طلبتها الآن:

1. **تهجير قواعد البيانات للمنصة** — تسجيل كل قاعدة بيانات حالية (السحابية والمحلية على 192.168.100.66) في `databases`، ربط كل موقع بقاعدته في `site_databases`، ثم تشغيل تهجير فعلي عبر الوكيل مع تحقّق من عدد الجداول والصفوف بعد النقل وسجل لكل خطوة.
2. **تفعيل النسخ الاحتياطي فعلياً** — سياسة لكل مجموعة مواقع (يومي للنشِط، أسبوعي للخامل)، ثلاث نسخ لكل ملف مهم موزّعة بين سيرفر محلي وسيرفر وجهة وتخزين سحابي، تشفير قبل النقل، وفحص استعادة دوري يُعلِم عند فشل النسخة.
3. **تقسيم المواقع إلى مجموعات** — تصنيف تلقائي لكل المواقع حسب تحليل بياناتها: النطاق ونوع الخدمة والسيرفر المضيف وحالة التشغيل وحجم قاعدة البيانات ووتيرة النشاط. تُخزَّن المجموعة على الموقع وفي `site_groups`، وتصبح وحدة التنفيذ للنسخ الاحتياطي والتحديث الجماعي والاستعلام الجماعي، مع إمكانية تعديل المجموعة يدوياً.
