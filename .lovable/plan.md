# مركز الأدوار والصلاحيات والعلاقات

الهدف: صفحتان جديدتان تجعلان إدارة المواقع وقواعد البيانات والسيرفرات والتخزين تمرّ عبر «من يملك ماذا» و«ما المرتبط بماذا»، بدل التنقّل بين عشرات الصفحات. لا حذف لأي جدول أو بيانات.

## 1) صفحة «الأدوار والصلاحيات» — `/access`

قائمة أقسام عمودية داخل الصفحة (نفس أسلوب مركز قواعد البيانات، عربي RTL):

- **أعضاء المنصة**: كل مستخدم مع دوره (مالك / مدير / محرر / مشاهد)، تغيير الدور، الدعوات المعلّقة، وحماية حساب المالك الدائم كما هي.
- **مصفوفة الصلاحيات**: جدول الأدوار × الصلاحيات (المواقع، البنية التحتية، الوكيل، قواعد البيانات، الأمان، الفريق، الأعمال) مع علامة واضحة لما يملكه كل دور.
- **صلاحيات لكل موقع**: اختيار موقع ثم تحديد من يصل إليه ومستوى وصوله (قراءة / تحرير / إدارة)، مع إضافة وإزالة المستخدمين من الموقع.
- **صلاحيات لكل سيرفر وقاعدة بيانات**: نفس الفكرة — من يملك تشغيل الأوامر، قراءة الجداول، الكتابة، تغيير البنية.
- **سجل التغييرات**: من غيّر أي دور أو صلاحية ومتى.

كل تغيير يمرّ بتأكيد، ويُفحص في الخادم أيضاً وليس في الواجهة فقط.

## 2) صفحة «علاقات المواقع» — `/relations`

- اختيار موقع (بالاسم أو رمزه `S######`) وعرض سلسلته كاملة:
  `الموقع ← قاعدة البيانات ← السيرفر ← الوكلاء ← النطاق/الشهادة ← التخزين ← النسخ الاحتياطية ← التنبيهات`
- كل عنصر رابط ينقل إلى صفحته مع اختياره مسبقاً.
- **الروابط الناقصة** تظهر بلون تحذيري (موقع بلا قاعدة، قاعدة بلا سيرفر، سيرفر بلا وكيل، موقع بلا نطاق/نسخ احتياطية) مع زر «ربط الآن» يفتح نافذة اختيار ويحفظ الربط مباشرة.
- **جدول عام**: كل المواقع في جدول واحد بأعمدة (قاعدة / سيرفر / وكيل / نطاق / تخزين / نسخ) وعلامة ✓ أو ✗ لكل عمود، مع تصفية «أظهر الناقص فقط» وتصدير CSV.
- عدّادات أعلى الصفحة: عدد المواقع المكتملة الربط مقابل الناقصة.

## 3) الوصول إليهما

زرّان جديدان في الشريط الجانبي: «الأدوار والصلاحيات» و«علاقات المواقع»، يظهران حسب صلاحية المستخدم.

## تفاصيل تقنية

- طُرق جديدة: `src/routes/_authenticated/access.tsx` و`src/routes/_authenticated/relations.tsx`؛ إضافة الروابط في `src/components/layout/AppSidebar.tsx`.
- إعادة استخدام `src/lib/permissions.ts` و`use-permissions` و`RoleGate`؛ لا تغيير في الأدوار الأربعة ولا في حماية المالك الدائم.
- الصلاحيات الدقيقة لكل موقع/سيرفر/قاعدة تُقرأ وتُكتب عبر `site_user_access` و`site_users` و`user_roles` و`server_access` الموجودة؛ إن نقص عمود مطلوب تُضاف هجرة واحدة مع GRANT وسياسات RLS كاملة (إضافة فقط، بلا حذف).
- العلاقات تُبنى بدالة خادم جديدة تجمع من `websites`, `site_databases`/`databases`, `servers`, `agent_instances`, `hn_domains`/`ssl_certificates`, `storages`, `site_backups`, `alert_rules` — على غرار `getEntityRelations` الحالية لكن لكل المواقع دفعة واحدة.
- كل دوال الكتابة محميّة بـ`requireSupabaseAuth` + فحص الدور في `src/lib/roles.server.ts`.

## ضمانات

- لا حذف لأي جدول أو صف أو صفحة قائمة.
- لا تغيير في شكل مركز قواعد البيانات أو بقية الصفحات.
- حساب المالك الدائم يبقى محمياً ولا يُعدّل دوره.
