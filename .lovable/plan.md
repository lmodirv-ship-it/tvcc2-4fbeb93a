# تطوير الصفحات الحالية: الأدوار والصلاحيات والعلاقات

الهدف: تطوير الصفحات الموجودة فقط — لا صفحات جديدة — لتصبح إدارة المواقع وقواعد البيانات والسيرفرات والتخزين مبنية على «من يملك ماذا» و«ما المرتبط بماذا». لا حذف لأي جدول أو بيانات.

## 1) تطوير صفحة «المستخدمون والفريق» (`/users`)

- **مصفوفة الصلاحيات**: تصبح قابلة للقراءة بوضوح (أدوار × صلاحيات مجمّعة: المواقع، البنية التحتية، الوكيل، قواعد البيانات، الأمان، الفريق، الأعمال).
- **تبويب جديد داخل نفس الصفحة: «صلاحيات لكل موقع»** — اختيار موقع ثم تحديد من يصل إليه ومستوى وصوله (قراءة / تحرير / إدارة)، مع إضافة وإزالة المستخدمين.
- **تبويب «صلاحيات السيرفرات وقواعد البيانات»** — من يشغّل أوامر الوكيل، يقرأ الجداول، يكتب، يغيّر البنية.
- كل تغيير بتأكيد + تسجيل في سجل النشاط، وحماية حساب المالك الدائم كما هي.

## 2) تطوير صفحة «خريطة العلاقات» (`/topology`)

- عرض سلسلة كل موقع كاملة: `الموقع (S######) ← قاعدة البيانات ← السيرفر ← الوكلاء ← النطاق/الشهادة ← التخزين ← النسخ الاحتياطية ← التنبيهات`.
- **جدول شامل لكل المواقع** بأعمدة (قاعدة / سيرفر / وكيل / نطاق / تخزين / نسخ) وعلامة ✓ أو ✗، مع تصفية «أظهر الناقص فقط» وتصدير CSV.
- **الروابط الناقصة** بلون تحذيري مع زر «ربط الآن» يفتح نافذة اختيار ويحفظ الربط مباشرة.
- عدّادات أعلى الصفحة: المواقع المكتملة الربط مقابل الناقصة.
- كل عنصر رابط ينقل إلى صفحته مع اختياره مسبقاً.

## 3) تطوير صفحة «المواقع» (`/websites`)

- عمود «الارتباط» لكل موقع يلخّص بشكل مصغّر: قاعدة/سيرفر/نطاق/نسخ، وزر ينقل إلى خريطة العلاقات مع اختيار الموقع.

## تفاصيل تقنية

- تعديل الملفات القائمة فقط: `src/routes/_authenticated/users.tsx`, `src/routes/_authenticated/topology.tsx`, `src/routes/_authenticated/websites.tsx`، مع مكوّنات صغيرة جديدة عند الحاجة تحت `src/components/`.
- إعادة استخدام `src/lib/permissions.ts` و`use-permissions` و`RoleGate` دون تغيير الأدوار الأربعة.
- الصلاحيات الدقيقة تُقرأ وتُكتب عبر الجداول الموجودة `site_user_access`, `site_users`, `user_roles`, `server_access`؛ إن نقص عمود مطلوب تُضاف هجرة واحدة (إضافة فقط) مع GRANT وسياسات RLS كاملة.
- العلاقات تُجمع بدالة خادم توسّع منطق `getEntityRelations` لتشمل كل المواقع دفعة واحدة، من `websites`, `site_databases`/`databases`, `servers`, `agent_instances`, `hn_domains`/`ssl_certificates`, `storages`, `site_backups`, `alert_rules`.
- دوال الكتابة محميّة بـ`requireSupabaseAuth` + فحص الدور في `src/lib/roles.server.ts`.

## ضمانات

- لا صفحات جديدة، ولا حذف لأي جدول أو صف أو صفحة قائمة.
- لا تغيير في شكل مركز قواعد البيانات أو بقية الصفحات.
- حساب المالك الدائم يبقى محمياً ولا يُعدّل دوره.
