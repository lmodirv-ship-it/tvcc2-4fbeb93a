# تفعيل الأزرار والمهام والأدوار وربطها بالعلاقات

الهدف: في صفحات السيطرة الفيدرالية (الوكيل، دوكر، نجينكس، قواعد البيانات) يصبح كل زر منفّذاً فعلياً، محكوماً بدور المستخدم ودور الوكيل، ومعروضاً معه سياق الكيانات المرتبطة.

## 1. تفعيل الأزرار فعلياً (لا زر بلا أثر)

لكل زر في الصفحات الأربع مسار تنفيذ حقيقي عبر أمر وكيل موقّع، مع:
- حالة انتظار على الزر نفسه أثناء التنفيذ.
- عرض نتيجة الأمر (نجاح/فشل + المخرجات) في بطاقة تحت الجدول.
- رسالة عربية واضحة عند الفشل بدل الصمت (السيرفر بلا وكيل / الوكيل غير متصل / صلاحية ناقصة / الأمر غير مفعّل لهذا الوكيل).
- تأكيد إجباري + خيار «محاكاة» للأوامر الخطرة (إعادة تشغيل، حذف حاوية، تطبيق DDL، استعادة نسخة).
- الأزرار التي لا يمكن تنفيذها تظهر معطّلة مع سبب الشرح عند المرور عليها، بدل أن تبدو عاملة ثم تفشل.

جرد مكتوب: جدول لكل صفحة يحدد الزر / ما ينفّذه / شرط ظهوره — يُضاف إلى تقرير نهائي.

## 2. الأدوار — مستوى المستخدم ومستوى الوكيل

**أدوار المستخدم (مالك / مدير / محرر / مشاهد):**
- توسيع مصفوفة الصلاحيات الحالية بصلاحيات دقيقة للصفحات الأربع: تشغيل أوامر الوكيل، إدارة دوكر، إدارة نجينكس، قراءة قواعد البيانات، الكتابة في الجداول، تنفيذ DDL، استيراد/تصدير.
- المشاهد: قراءة فقط. المحرر: قراءة + عمليات آمنة. المدير والمالك: كل شيء.
- التحقق مزدوج: إخفاء/تعطيل في الواجهة **و** فحص فعلي في كل دالة خادم قبل وضع الأمر في الطابور.

**أدوار الوكيل على السيرفر (web / db / backup / security / healer / monitor):**
- كل مهمة تُصنَّف للأدوار المسموح لها بتنفيذها؛ الوكيل ذو الدور غير المطابق لا تُسند له المهمة.
- جدول المهام في صفحة الوكيل يعرض عمود «الأدوار المخوّلة» وزر تفعيل/تعطيل لكل دور، مع «تفعيل حسب الدور» دفعة واحدة.
- عند وجود أكثر من وكيل على السيرفر، يختار النظام تلقائياً الوكيل صاحب الدور المناسب والأفضل اتصالاً، مع إمكانية الاختيار اليدوي.

## 3. بطاقة العلاقات في كل صفحة

مكوّن موحّد «الكيانات المرتبطة» يظهر عند اختيار أي عنصر، ويعرض السلسلة:

```text
الموقع (S######) → قاعدة البيانات → السيرفر → الوكلاء → النطاق/الشهادة → الحاويات ← إعداد نجينكس → النسخ الاحتياطية → التنبيهات
```

- كل عنصر في البطاقة رابط ينقل إلى صفحته مع اختياره مسبقاً.
- إبراز الروابط الناقصة (موقع بلا قاعدة، قاعدة بلا سيرفر، سيرفر بلا وكيل، حاوية بلا موقع) مع زر «ربط الآن» يصلح العلاقة مباشرة.
- عدّادات حية: عدد المواقع/القواعد/الحاويات/الأوامر الجارية لكل سيرفر.

## 4. التحقق بعد التنفيذ

جولة بمتصفح حقيقي بصلاحية المالك على الصفحات الأربع، والضغط على كل زر، وتسليم جدول: الصفحة / الزر / الدور المطلوب / النتيجة. ما يتطلب وكيلاً محدّثاً على سيرفر حقيقي يُذكر صراحة كغير مثبت من السحابة.

## تفاصيل تقنية

- توسيع `src/lib/permissions.ts` بمفاتيح: `agent.run`, `agent.capability`, `docker.manage`, `nginx.manage`, `db.read`, `db.write`, `db.ddl` — وإضافة فحصها في `src/hooks/use-permissions.ts` وفي دوال الخادم عبر `src/lib/roles.server.ts`.
- إضافة `allowedRoles` لكل أمر في `src/lib/server-commands.ts` بجانب التصنيف والخطورة الحاليين، واستعمالها في `agent-roles.functions.ts` عند اختيار الوكيل المنفّذ.
- مكوّن جديد `src/components/relations/EntityRelations.tsx` + دالة خادم `getEntityRelations` (في `federated.functions.ts`) تُرجع سلسلة العلاقات من `websites`, `databases`/`site_databases`, `servers`, `agent_instances`, `hn_domains`/`ssl_certificates`, `server_containers`, `nginx_configs`, `site_backups`, `alert_rules`.
- تُستعمل البطاقة في `federated.agents.tsx`, `federated.docker.tsx`, `federated.nginx.tsx`, `federated.db.tsx`.
- لا هجرات جديدة إلا عند الحاجة لعمود `allowed_roles` في `agent_capabilities`؛ عندها هجرة واحدة مع GRANT وسياسات RLS كاملة.
