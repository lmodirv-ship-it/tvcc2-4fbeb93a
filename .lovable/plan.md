# منارة — مركز التوجيه الحي

منارة تصبح "المصدر الوحيد للحقيقة" لعناوين مشاريع المجموعة: كل تطبيق APK أو PWA أو موقع يسأل منارة عن العنوان الحالي لمشروعه (بالمعرّف الثابت، لا بالنطاق)، فيفتح مشروعه الصحيح دائماً حتى لو تغيّر النطاق أو المنفذ.

## ما سيراه المستخدم

- زر جديد **منارة** في القائمة الجانبية (تحت "المواقع") يفتح صفحة `/manara` بنفس تصميم الصورة:
  - بطاقة مركزية "منارة — مركز التوجيه الحي" مع مشهد المنارة/الكرة المتوهجة (تُولَّد صورة الخلفية) وحقل بحث/إدخال عنوان جديد + زر "نشر".
  - بطاقة **المسارات الحية**: كل مسار (خادم + منفذ) وحالة اتصاله.
  - بطاقة **تحديثات العناوين**: حلقة إحصاء (قيد النشر / مكتمل / معلّق / فشل).
  - بطاقة **المواقع والتطبيقات**: لكل مشروع بطاقاته (موقع ويب، APK، PWA، خدمة API) وحالتها.
  - بطاقة **نقاط التوجيه**: DNS، Nginx، الخادم، الوكيل — مع **تصحيح ذاتي**: إذا تغيّر Nginx أو DNS أو اسم النطاق أو حدث خطأ في التوجيه، تكتشف منارة الانحراف عن العنوان المعتمد وتُعيد التوجيه الصحيح تلقائياً عبر أوامر الوكيل (إعادة كتابة قواعد Nginx وسجلات DNS) ثم تعيد الفحص وتنشر التصحيح على منظومة مواقع المجموعة.
  - شريط **النشاط المباشر** أسفل الصفحة (آخر الأحداث لحظياً).
- صفحة تفاصيل مشروع داخل منارة: العنوان الحالي، سجل العناوين السابقة، نتيجة آخر فحص، وأزرار "تغيير العنوان" و"إعادة الفحص" و"إعادة النشر".
- **رمز منارة** (شارة صغيرة قابلة للتضمين) يظهر أسفل الصفحة الرئيسية لكل مواقع المجموعة، ويعرض عند الضغط حالة العنوان الحالي وروابط APK/PWA الصحيحة.

## آلية العمل

```text
هوية ثابتة (project_key)  ->  منارة  ->  العنوان الحالي  ->  الخادم + المنفذ
        APK / PWA / موقع  --GET-->  /api/public/manara/resolve?key=ID00123
```

عند تغيير عنوان مشروع:
1. تسجيل العنوان الجديد كـ "قيد النشر".
2. فحص تلقائي (HTTP + بصمة هوية المشروع) للتأكد أن المشروع الصحيح يعمل على العنوان.
3. أرشفة العنوان السابق في سجل العناوين مع تاريخ التحويل.
4. نشر التحديث لكل المواقع/التطبيقات المرتبطة (تحديث سجلات + استدعاء webhooks + إبطال الكاش).
5. الحالة تصبح "مكتمل"، أو "فشل" مع سبب واضح وإمكانية التراجع للعنوان السابق.

بصمة الهوية تمنع الخطأ الشائع: منارة لا تقبل عنواناً جديداً إلا إذا أعاد `project_key` المطابق، فلا يُفتح مشروع مكان آخر.

## التفاصيل التقنية

### جداول جديدة (مع GRANT + RLS)
- `manara_projects` — الهوية الثابتة: `project_key` (يستخدم `site_code` IDXXXXX)، الاسم، `website_id`، `current_address_id`، الحالة، المالك.
- `manara_addresses` — كل عنوان: `project_id`، `url`، `host`، `port`، `server_id`، `kind` (web/api/apk/pwa)، `is_current`، `verified_at`، `retired_at`.
- `manara_endpoints` — التطبيقات المرتبطة: نوع (`web`,`apk`,`pwa`,`service`)، رابط التوزيع، الإصدار، آخر حالة.
- `manara_updates` — عمليات التحديث: من عنوان → إلى عنوان، الحالة (`publishing|completed|pending|failed`)، السبب، التوقيتات.
- `manara_events` — سجل النشاط المباشر للبطاقة السفلية.

RLS: الكتابة لمالك السجل و`system_owner`/`admin` عبر `can_manage`. أما القراءة فتُمنح لـ `anon` مباشرة على جداول التوجيه (`manara_projects`, `manara_addresses`, `manara_endpoints`) للسجلات النشطة فقط وبأعمدة توجيه آمنة (المعرّف، العنوان الحالي، النوع، روابط APK/PWA، حالة التحقق) بدون أي بيانات مالك أو أسرار — حتى يستطيع أي تطبيق أو موقع في المجموعة حلّ عنوانه فوراً دون عرض واجهة مشروع خاطئ. جداول `manara_updates` و`manara_events` تبقى مغلقة على المالك/الإدارة.

### نقاط API
- المواقع المسجّلة والتابعة لمنظومة **HN-GROUPE** **لا تحتاج أي API**: تحلّ عنوانها مباشرة من جداول منارة بصلاحية `anon` (قراءة مباشرة للعنوان الحالي المُتحقق منه) — بلا وسيط وبلا احتمال عرض واجهة خاطئة. نقاط الـ API أدناه مخصّصة فقط للتطبيقات الخارجية (APK/PWA) والمواقع خارج المنظومة.
- `GET /api/public/manara/resolve?key=IDXXXXX` (CORS مفتوح، بدون PII): يعيد العنوان الحالي + روابط APK/PWA + إصدارها + `etag`.
- `GET /api/public/manara/badge.js`: سكربت خفيف يضيف رمز منارة أسفل صفحة أي موقع في المجموعة ويربطه تلقائياً بالعنوان الصحيح لتطبيقاته.
- `POST /api/public/manara/announce`: يستقبل إعلان تغيّر العنوان من الوكيل/الموقع، موقّع بـ HMAC عبر `HN_HUB_VERIFICATION_SALT`.

### دوال الخادم (`src/lib/manara.functions.ts`)
`listManara`, `getManaraProject`, `changeAddress` (تسجيل + فحص + أرشفة + نشر)، `verifyAddress`, `republish`, `rollbackAddress`.
الفحص والنشر يجريان داخل الـ handler (fetch + تحديث الجداول + تسجيل حدث).

### الواجهة
- `src/routes/_authenticated/manara.tsx` + `manara.$key.tsx` بتصميم الصورة (توهج أخضر/ذهبي على خلفية داكنة، توكنز التصميم الحالية فقط).
- إضافة العنصر إلى `AppSidebar.tsx` وترجمات `ar/fr/en`.
- المشهد المركزي يبقى **متحركاً دائماً**: الخلفية **سماء ليلية بنجوم متحركة ووامضة** (Canvas/SVG)، وألوان **المنارة تتبدّل بسلاسة** (أخضر ← ذهبي ← سماوي) مع إشعاع دوّار مستمر، والخطوط الرابطة يميناً ويساراً تنبض كالبرق (رسوم CSS/Canvas خالصة، بلا استعلامات). أما **جلب البيانات فكل 5 دقائق فقط** عبر TanStack Query (`refetchInterval: 300000`) لتخفيف الحمل، بينما المهام والعلاقات والأدوار بين مواقع المجموعة وتطبيقاتها تُنفَّذ فعلياً في جداول البيانات (`manara_*` + `tvcc_service_links`) لا في الواجهة.
